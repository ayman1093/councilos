CouncilOS Kernel — M1 Specification
The Deterministic Core
Status: Approved (pending engineer review at the gate)
Depends on: M0 (merged), ADR-0001
Related: CLAUDE.md, tests/m0_golden.rs

1. Goal
M1 turns the silent skeleton into a living deterministic core:one Nop instruction travels the complete governed path —policy → capability → resource lease → execution → event →evidence → state commit — and any session can be replayedfrom its event log to the same final state hash, withoutthe model present.

The promise remains auditable replay, not "full determinism".

2. Scope (closed list — nothing else enters this milestone)
HandlerHost trait — one trait, two implementations:
SubprocessHost: runs the handler in a separate OS process,communicating via stdin/stdout with length-prefixed JSON frames.No network, no file writes, no extra privileges.
InProcessHost: for fast tests — documented as panic-onlyisolation (its limitations are part of its doc contract).
The governed path for one instruction:
Policy check (allow/deny — single fixed policy set in M1)
Capability check (does the executor hold the required capability)
Resource lease (acquire → execute → release)
Execution via HandlerHost
Event emitted (with outcome: Completed / Rejected / Crashed / TimedOut)
Evidence hashed and wrapped by the Runtime (handlers never signtheir own evidence)
State commit (StateRecord with prev_hash chain)
EventStore (initial) — append-only JSON-lines log:
Atomic writes (tempfile → fsync → rename — learned from Bello)
Load + replay: rebuild state from the log, verify final hash
replay command — load a session log, re-apply events,assert the final StateHash matches.
3. Acceptance tests (the three gates — no merge without all)
Gate A — Deterministic replay:Same event log replayed N times (≥1000 via proptest, once acrosstwo separate processes) must produce the byte-identical finalStateHash.

Gate B — Fault isolation:A handler that calls abort() (SIGABRT) must NOT crash theruntime. The event log must record outcome = Crashed { signal }and the state must remain valid and unchanged by the crash.

Gate C — Governance rejection:An instruction submitted without the required capability must berejected at the gate. The event log must record outcome = Rejected { reason } and the state must remain unchanged.

4. Binding rules
M1 is fully synchronous — no tokio. (Revisit at 0.2+ via ADR only.)
The Runtime hashes and wraps all evidence.
Crashes are recorded events, never exceptions that escape.
Golden hashes from M0 must remain green — extending tests/,never modifying them.
Errors are surfaced, never swallowed.
5. Known constraints & carried decisions
Linux-only subprocess testing in CI (documented limitation).
sequence is u64, canonicalized via checked i64 conversion.
Timestamps are metadata — excluded from every hash.
Domain separation between hash types (instruction/event/state)is a known gap — requires schema bump; tracked as a future ADR,not to be fixed casually in M1.
$-key collision fix (ADR-0002) lands before or with M1 core work.
6. Out of scope (forbidden in M1)
LLM drivers / Multi-agent / Five-layer memory / Networking /Federation / Cedar integration / Any GUI / Any new documentsbefore working code (P53).

7. Estimation reference
Independent AI-assisted review estimates: 40–80 focused hoursdepending on test depth. First-pass success probability is low(10–15%); expect 3–5 CI correction cycles. These numbers arefor planning only — human engineer's own estimate takesprecedence at the gate.
